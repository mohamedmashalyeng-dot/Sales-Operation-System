# Frontend Architecture

## Source Of Truth

Default UI source of truth is `frontend/src`.

Build output is `frontend/out`, generated by:

```bash
npm run ui:build
```

The backend serves `frontend/out` by default when `frontend/out/index.html` exists and `KBC_UI` is not `legacy`.

## Legacy Frontend

Root files remain important fallback/runtime assets:

- `index.html`
- `app.js`
- `styles.css`
- `developer.css`
- `sw.js`

They are served when `frontend/out` is missing or `KBC_UI=legacy`.

## Routing

React routing lives under:

- `frontend/src/router/config.tsx`
- `frontend/src/router/index.ts`
- page components in `frontend/src/pages/`

Vite dev server proxies `/api` and `/uploads` to `VITE_API_PROXY_TARGET`.

## API Client And Data Loading

Main backend mapping is in `frontend/src/store/backendSync.ts`.

Startup flow:

1. `WorkspaceProvider` calls `loadBackendWorkspace`.
2. `loadBackendWorkspace` fetches `GET /api/bootstrap`.
3. It then loads page-sized sections in parallel: leads, tasks, applications, events, meetings and calls.
4. It maps backend rows into frontend `WorkspaceState`.

Integration overview:

- `loadBackendIntegrationOverview` calls `GET /api/integrations/overview`.
- `WorkspaceProvider` refreshes integration overview and uses a timer when sync is active.

## Pagination

The React loader uses page-sized requests:

- Leads: `/api/leads?limit=...&include_total=true`
- Tasks: `/api/tasks?status=all&limit=...`
- Applications: `/api/applications?limit=...`
- Events: cursor pagination through `/api/events`
- Meetings: cursor pagination through `/api/meetings`
- Calls: offset pagination through `/api/zoom/calls`

Do not replace these with global full-workspace loads.

## State

`WorkspaceProvider` still contains local/demo state behavior and many local mutation helpers. In backend mode, loaded backend state replaces local state, and authenticated backend failures show the backend sign-in screen.

## Service Worker

`sw.js` belongs to the legacy/static shell. It:

- Caches root legacy shell assets with versioned query strings.
- Does not intercept localhost.
- Does not intercept `/api/*`.
- Falls back to `offline.html` for navigation failures.

The React build currently does not have a separate service worker in `frontend/out`.

## Warnings For New Frontend Work

- Do not fetch all CRM data for a single page.
- Do not fetch from render loops.
- Do not add duplicate polling for integration overview.
- Do not trigger provider full sync when a page opens.
- Do not manually edit `frontend/out`; edit `frontend/src` and rebuild.
- Do not add a second API client pattern unless replacing an existing one intentionally.
- Be careful with legacy `app.js`; it has its own local fallback and API wrapper, so changes there may not affect the React UI.
