# Architecture

## Active Runtime Flow

```mermaid
flowchart TD
  Browser --> Static[server/static-files.js]
  Browser --> API[/api/*]
  Static --> ReactOut[frontend/out]
  Static --> LegacyRoot[index.html app.js styles.css sw.js]
  API --> Router[server/routes/index.js]
  Router --> Open[open routes: health login callbacks]
  Router --> Direct[direct DB routes]
  Router --> WorkspaceRoutes[workspace load fallback routes]
  Direct --> Storage[server/storage.js]
  WorkspaceRoutes --> Storage
  Storage --> Postgres[(PostgreSQL/Neon)]
  Storage --> Mongo[(MongoDB optional)]
  Storage --> Json[data/pathway-db.json local fallback]
  Router --> Auth[server/auth.js]
  Router --> Authorization[server/authorization.js]
  Jobs[server/jobs.js] --> Gmail
  Jobs --> Eventbrite
  Jobs --> Zoom
  Jobs --> Zoho
```

## Active

- `server.js`: creates the Node HTTP server, sends `/api/*` into `Routes.handleApi`, serves browser files otherwise, starts jobs and monitoring after listen.
- `server/routes/index.js`: route dispatcher and API middleware. It applies security headers, no-store API cache headers, parses bodies, checks session cookies for protected routes, then tries route groups.
- `server/storage.js`: storage abstraction. PostgreSQL is the production path when `DATABASE_URL` starts with `postgres://` or `postgresql://`.
- `server/auth.js`: login, sessions, password reset, user management, developer account rules, public user shaping.
- `server/authorization.js`: team/member authorization and record ownership checks.
- `frontend/src`: React/Vite frontend source.
- `frontend/out`: generated browser app served by default when present.
- `server/integrations`: Gmail, Eventbrite, Zoom, Zoho, Meta and Apollo provider code.
- `sql/`: migration/helper SQL used for production schema and performance changes.

## Legacy But Still Required

- `index.html`, `app.js`, `styles.css`, `developer.css`, `sw.js`: fallback UI when `frontend/out/index.html` is missing or `KBC_UI=legacy`.
- Workspace-loaded fallback route handlers in many `server/routes/*.js` files. The dispatcher reaches these after direct DB routes by calling `Storage.loadDb()`.
- JSON file storage at `data/pathway-db.json`: local fallback when `DATABASE_URL` is absent.
- MongoDB support: still in `server/storage.js`, but current production guidance uses PostgreSQL.

## Generated

- `frontend/out/`: Vite build output. Do not edit manually.
- `frontend/auto-imports.d.ts`: generated by the Vite auto-import plugin.
- `dist/`, `tsconfig.build.tsbuildinfo`: TypeScript/Nest build output/cache.
- `package-lock.json` and `frontend/package-lock.json`: dependency lock files, not hand-edited.

## Unused / Cleanup Candidate

- `src/`: NestJS modules exist and `npm run start:dev` uses Nest, but `server.js` is the active production entrypoint.
- `sql/neon_normalized_schema.sql`: describes normalized reporting tables from `app_state`; current active app tables are `app_*` tables created by `server/storage.js` and migrations.
- Root legacy frontend may be retained as fallback, but it duplicates API calling/state logic with the React frontend.

## Unknown / Verify Before Changing

- Whether production Hostinger builds `frontend/out` or deploys it prebuilt.
- Whether Hostinger env vars are supplied by dashboard, `.env.hostinger`, `hostinger.env`, or another runner mechanism.
- Which provider accounts own Gmail, Eventbrite, Zoom, Zoho, Meta and Apollo.

## Runtime Boundary

Frontend:

- Source: `frontend/src`.
- API client/mapping: `frontend/src/store/backendSync.ts`.
- Workspace state and backend login handling: `frontend/src/store/WorkspaceProvider.tsx`.
- Vite config/build output: `frontend/vite.config.ts` with `outDir: 'out'`.

Backend:

- Entry: `server.js`.
- Router: `server/routes/index.js`.
- Business modules: `server/leads.js`, `server/tasks.js`, `server/emails.js`, `server/events.js`, `server/applications.js`, etc.
- Integrations: `server/integrations/*.js`.
- DB/storage: `server/storage.js`.

Hostinger:

- Start file: `server.js`.
- Start command: `npm start`.
- Node engine: `>=18` in `package.json`; project plan recommends Node 20+ for production.
